Three Approaches for field13 Dashboard

We already agreed on Approach 1 — here are the trade-offs

✅ Approach 1: Custom Obsidian Plugin (Recommended)

Follow the Obsidian-Dashboard guide exactly. Preact + TypeScript + Tailwind plugin installed at .obsidian/plugins/field13-command-center/. Full data layer with headless Claude scripts writing to data/*.json.

Pros

  • Full control over UI & interactions
  • No network needed (offline-first)
  • Follows the established guide
  • Ghibli pixel-art possible

Cons

  • Requires building & bundling
  • Plugin must be maintained

Approach 2: Dataview + CSS Snippets

Use Obsidian Dataview plugin to query vault metadata and render tables/lists. Style with CSS snippets. All in markdown.

Pros

  • Much faster to set up
  • No build step
  • Easy to edit

Cons

  • Limited interactivity
  • No one-click skill buttons
  • No custom card layouts
  • Can't style as Ghibli/pixel-art easily
  • Requires Dataview knowledge

Approach 3: Standalone Web Dashboard

Build a React web app (like the existing field13 website) that reads vault files via a local server. Runs in browser side-by-side with Obsidian.

Pros

  • Richer animations & interactions
  • Any tech stack possible

Cons

  • Not inside Obsidian (separate window)
  • Requires local server running
  • Can't use Obsidian APIs
  • More complex to set up

Approach 1 is the strongest — the rest of the design assumes we're building a custom plugin.
